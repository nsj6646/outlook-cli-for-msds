# 도메인 문서 (Domain Docs)

에이전트 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 참조해야 하는지에 대한 규칙입니다.

## 탐색 전 읽어야 할 파일

- 루트 폴더의 **`CONTEXT.md`** 파일, 또는
- 루트 폴더에 **`CONTEXT-MAP.md`**가 존재할 경우, 각 컨텍스트별 `CONTEXT.md`를 가리키므로 관심 있는 주제와 관련된 각각의 파일을 읽으십시오.
- **`docs/adr/`** — 작업할 영역과 관련된 기존 ADR(아키텍처 결정 레코드)들을 읽으십시오. 멀티 컨텍스트 저장소의 경우, 컨텍스트 범위 내 결정을 위해 `src/<context>/docs/adr/`도 확인하십시오.

만약 이 파일들이 존재하지 않는다면 **아무런 경고 없이 계속 진행**하십시오. 존재하지 않는다고 경고하거나 먼저 생성하라고 제안하지 마십시오. `/domain-modeling` 스킬(또는 `/grill-with-docs` 및 `/improve-codebase-architecture`를 통해 유입)을 수행하는 과정에서 필요에 따라 나중에 생성하게 됩니다.

## 파일 구조 (File structure)

단일 컨텍스트 저장소 (대부분의 저장소):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

멀티 컨텍스트 저장소 (루트에 `CONTEXT-MAP.md`가 있는 경우):

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← 시스템 전반의 결정
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← 컨텍스트 특정 결정
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## 용어집(Glossary) 단어 사용

이슈 제목, 리팩터 제안, 가설, 테스트 이름 등에서 도메인 개념을 명명할 때 반드시 `CONTEXT.md`에 정의된 용어를 사용하십시오. 용어집에서 명시적으로 기피하는 동의어를 임의로 혼용하여 사용하지 마십시오.

필요한 개념이 용어집에 없다면, 프로젝트가 쓰지 않는 언어를 사용 중이거나(재고 필요) 실제 공백이 존재하는 것( `/domain-modeling` 시점에 반영하도록 기록)입니다.
