# ADR 0003: MailDistributionContext 통합 및 감사 로그 자가 정리 보존 정책 결정

## 상태 (Status)
승인됨 (Accepted)

## 컨텍스트 (Context)
이전까지 엑셀 파싱 및 MSDS 파일 자동 수집, 메일 본문 조립 등의 핵심 비즈니스 로직이 CLI 제어 루프(`send_bulk_mails_from_excel`)에 산재해 있어, 진입점 자체가 복잡해지는 마찰(Friction)이 있었습니다.
이 비즈니스 정책들을 하나의 단순하고 명확한 인터페이스 뒤로 숨기는 깊은 모듈(Deep Module) 설계가 요구되었습니다.
또한 배포 과정에서 발생하는 각종 매칭 오류와 예외 사항을 검수하기 위해 별도의 감사 로그(Audit Log)를 남기되, 로그 파일이 무한히 누적되어 폴더가 오염되거나 파일이 비대화되는 것을 방지하는 보존 대책이 필요합니다.

## 결정 (Decision)
1. **MailDistributionContext로의 통합(Collapse)**:
   - 엑셀 데이터 파일 경로, MSDS 보관 폴더, 기본 발신자 이메일만을 입력 인자 인터페이스로 수용하는 `MailDistributionContext` 클래스를 정의합니다.
   - 모듈 내부에서 엑셀 읽기, 제품코드 매칭, 표 조립을 완벽히 캡슐화하고 외부에는 완성되어 전송 가능한 정보 객체 목록(`List[MailJob]`)만을 노출시킵니다.
2. **오류 정책**:
   - 엑셀 파일 누락과 같은 구조적 오류는 즉시 중단(ValueError 전파)을 가하고, 특정 수신인의 MSDS 파일이 없거나 예약 발송 시간이 잘못된 형태의 일반 오류는 해당 행만 건너뛴(Skip) 뒤 감사 로그를 적고 정상 수신인 목록만 반환하는 유연한 설계를 적용합니다.
3. **타임스탬프 기반 개별 로그 및 보존 정책**:
   - 실행할 때마다 고유한 로그 파일(`logs/distribution_YYYYMMDD_HHMMSS.log`)을 새로 생성하여 기록합니다.
   - 단, 디스크 오염을 방지하기 위해 프로그램 실행 시 `logs/` 디렉토리 내에서 수정 일자 기준으로 **7일 보존 기한이 경과한 오래된 로그 파일들을 자동으로 검색하여 청소(Auto-cleanup)**하는 자동 정리 로직을 `MailDistributionContext` 모듈 내에 장착시킵니다.

## 결과 (Consequences)
- **장점**: CLI 진입점 스크립트는 이 모듈을 호출하여 단 한 줄로 발송 대상을 도출할 수 있게 되어 매우 얇은 인터페이스(Thin Interface)를 달성하고 재사용성이 대폭 증가합니다. 발송 이력을 세션별로 안전하게 증적 보존하면서도 파일 자동 청소 기능 덕분에 용량이나 디렉토리 관리 측면에서 아주 쾌적하게 동작합니다.
- **단점**: 로그 파일이 실행마다 늘어났다가 기한 뒤에 지워지기 때문에, 7일보다 이전에 수행한 발송 로그에 대한 분석이 필요하다면 수동으로 파일을 미리 백업해 두어야 합니다.
