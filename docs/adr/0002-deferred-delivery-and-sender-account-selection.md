# ADR 0002: 아웃룩 배달 지연(Deferred Delivery) 및 동적 발신 계정 연동 결정

## 상태 (Status)
승인됨 (Accepted)

## 컨텍스트 (Context)
사용자는 각 고객사별로 개인 이메일 계정 또는 회사 공용 이메일 계정 중에서 발신용 계정을 선택하여 발송하고, 발송 시간을 예약할 수 있는 기능을 필요로 합니다.
또한 초기 운영 단계에서는 메일 오발송 사고를 예방하기 위해, 메일을 즉시 발송하지 않고 아웃룩의 '초안 보관함(Drafts)'에 메일을 생성해두고 사람이 최종 검수한 후 발송 버튼을 누르는 흐름이 강제되어야 합니다.

## 결정 (Decision)
1. **동적 발신 계정 설정**: `Recipients` 시트에 `From` 컬럼을 명시하여 각 행마다 발신할 메일 주소를 다르게 적을 수 있도록 합니다. 프로그램은 각 행을 발송할 때 `mail.SendUsingAccount` 속성에 해당 이메일 주소와 매칭되는 아웃룩 등록 계정 객체를 동적으로 바인딩합니다.
2. **예약 발송 (배달 지연)**: `Recipients` 시트에 `DeferredTime`(예약 발송 시간) 컬럼을 추가합니다. 프로그램은 이 컬럼에 날짜/시간(예: `YYYY-MM-DD HH:MM:SS` 형식)이 기재되어 있을 경우 아웃룩 MailItem의 `DeferredDeliveryTime` 속성에 해당 시간을 주입합니다.
3. **초안 보관함 저장**: 대량 발송을 시작할 때, 기본값으로 모든 메일을 초안 상태(`draft=True`)로 다룹니다. 백그라운드 환경이나 대량 발송 시에는 사용자의 화면에 여러 메일 창이 동시에 뜨는 것을 피하기 위해, `mail.Display()` 대신 `mail.Save()`를 호출하여 아웃룩의 초안 보관함(Drafts) 폴더에 안전하게 메일을 일괄 수집합니다. 실무자는 아웃룩을 열어 초안 보관함에서 메일 내용과 첨부파일을 검토한 후 최종 발송 처리를 합니다.

## 결과 (Consequences)
- **장점**: 대량 발송 메일에 대해 안전한 '사용자 검수 단계(Human-in-the-loop)'를 둘 수 있어 오발송 우려를 원천 차단합니다. 엑셀 한 줄로 어떤 계정으로 언제 보낼지 완벽히 제어할 수 있습니다.
- **단점**: 초안 보관함에 들어간 메일들은 사용자가 아웃룩 내에서 수동으로 발송 버튼을 눌러주어야 합니다. (추후 시스템에 신뢰가 쌓였을 때 이를 우회하여 백그라운드에서 즉시 다이렉트 발송할 수 있는 설정 플래그 `--no-draft` 또는 설정 변수를 호환 가능하게 설계해둡니다.)
